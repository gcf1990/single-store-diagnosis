# 邀约客户洞察大类导航定向变更设计

## 1. 文档性质
- 本文件是 `2026-07-27-invite-customer-insight-design.md` 的定向变更。
- 冲突处以本文件为准；未提及的数据源、字段清洗、去重、请求状态、权限边界和回归要求沿用旧设计。
- 本次只改邀约客户洞察的信息架构、关注点概述展示和锚点定位合同。
- 本次不改代码之外的业务口径，不扩展客户画像、统计、AI 总结、写回或跨模块导航。
- 本次不改试驾客户洞察。

## 2. 背景
- 邀约客户洞察已按旧设计上线。
- 当前邀约实现的问题是：第二部分展示细类 `focus`，点击后跳到单条证据卡。
- 试驾客户洞察基线是：概述只展示大类 `primaryLabel`，点击后跳到下方 `rating + primaryLabel` 分组。
- 用户已确认邀约侧采用试驾的大类分组锚点方式。
- 本次目标是把导航粒度从“细类证据卡”收敛为“满意度 + 大类分组”。

## 3. 目标与非目标
- V1 用户：单店或小区管理者复盘单通电话邀约。
- 目标阅读顺序：提及竞品 -> 客户关注点 -> 关注点具体数据。
- 第二部分只承担目录作用，展示客户关注大类。
- 第三部分承担证据阅读，保留所有细类、判定依据和 quote。
- 点击第二部分大类后，平滑滚动并聚焦第三部分对应的“满意度 + label”分组。
- 非目标：不新增客户画像、关注点占比、满意度分布、竞品榜、AI 改写总结、写回能力。
- 非目标：不合并证据，不丢 quote，不用 `focus` 兜底第二部分标签。
- 非目标：不新增独立目录导航、锚点菜单或侧边栏。
- 非目标：不改变 q31 查询、`eventId` 关联、lazy load、权限判断和试驾客户洞察。

## 4. 方案比较与选择
- 方案 A：继续点击到第一条细类。
- 问题：用户点击大类语义，却只看到第一条细类证据，会误判大类下证据数量。
- 结论：拒绝。
- 方案 B：新增目录导航。
- 问题：邀约详情是窄侧栏抽屉，新增目录会挤压证据区，也破坏与试驾的一致性。
- 结论：拒绝。
- 方案 C：复用试驾大类分组锚点。
- 做法：第二部分只展示 `rating + label` 的大类 chip，点击跳到第三部分同一组合的分组容器。
- 价值：与试驾基线一致，同一大类下多条细类证据可一次进入完整分组，不改变 q31 数据合同。
- 结论：采用方案 C。

## 5. 信息架构
- 客户洞察 Tab 内固定三段。
- 第一段：提及竞品。
- 第二段：客户关注点。
- 第三段：关注点具体数据。
- 第一段有竞品才显示，无竞品时整段隐藏。
- 第二段只显示可点击的大类标签。
- 第三段不新增“关注点具体数据”总标题，直接展示满意度分组卡。
- 第三段满意度分组标题直接使用“不满意关注点”“满意关注点”“中性关注点”“其他/未评级关注点”。

## 6. 提及竞品
- 标题固定为“提及竞品”。
- 只要 q31 某行 `competitor`、`compet_desc`、`compet_sum` 任一字段有值，该行参与竞品展示。
- 每个竞品组合独立成卡。
- 竞品去重键固定为 `competitor + compet_desc + compet_sum` 三字段完整组合。
- 完全相同组合只展示一次；任一字段不同则展示为不同卡。
- 每张卡保留竞品、竞品描述、竞品总结三个展示字段。
- 字段为空时不显示该字段行。
- 无竞品时不显示标题、空态、空壳或占位。
- 提及竞品不参与客户关注点标签，也不参与关注点证据分组。

## 7. 客户关注点
- 标题固定为“客户关注点”。
- 第二部分只显示 q31 大类 `label`。
- 第二部分禁止显示 q31 细类 `focus`。
- 第二部分禁止使用 `focus` 兜底生成标签。
- `label` 为空、空白或清洗后为空时，不生成第二部分标签。
- 同一满意度组内，同一 `label` 只显示一次。
- 同一 `label` 跨不同满意度组时分别显示。
- 满意度排序固定为：不满意、满意、中性、其他/未评级。
- 每个满意度组内的 `label` 使用中文 locale 稳定排序。
- 标签必须是 button。
- 键盘 Tab 可聚焦标签。
- Enter 和 Space 触发与点击一致的跳转。
- 标签 `aria-label` 应包含满意度和大类，例如“查看不满意关注点：价格权益的具体数据”。
- 如果没有任何非空 `label`，但第三部分有证据，则第二部分整段隐藏。

## 8. 关注点具体数据
- 第三部分直接渲染满意度分组卡，不新增总标题。
- 满意度分组顺序固定为：不满意、满意、中性、其他/未评级。
- 每个满意度分组下继续按 `label` 分组。
- `label` 有值时显示该大类标题。
- `label` 为空时归入“未分类”分组。
- “未分类”只用于第三部分保留证据，不反向生成第二部分标签。
- 每个 `label` 分组下保留所有细类 `focus` 独立证据卡。
- 不得把同一 `label` 下多个 `focus` 合并成一张卡。
- 不得只展示第一条 `focus`。
- 不得因为第二部分去重而删除第三部分证据。
- 证据卡标题优先使用 `focus`。
- `focus` 为空且 `label` 有值时，证据卡标题使用 `label`。
- `focus` 和 `label` 均为空时，证据卡标题使用“未命名关注点”。
- 证据卡继续展示满意度信息、满意度类别、满意度判定依据和 quote 气泡。
- quote 气泡继续区分客户、顾问和原文。

## 9. 字段与展示规则
- `label` 来源字段：`提取客户关注大类` / `label`。
- `focus` 来源字段：`提取大类下的具体关注点` / `focus`。
- `satisfaction` 来源字段：`提取客户满意度` / `satisfaction`。
- `satis_cate` 来源字段：`满意度类别` / `satis_cate`。
- `satis_support` 来源字段：`提取满意度判定依据` / `satis_support`。
- `quote` 来源字段：`引用` / `quote`。
- 竞品字段：`竞品` / `competitor`、`竞品描述` / `compet_desc`、`竞品总结` / `compet_sum`。
- 第二部分只读取 `label` 和 `satisfactionGroup` 生成导航。
- 第三部分读取 `label`、`focus`、`satisfaction`、`satis_cate`、`satis_support`、`quote` 生成证据。
- 竞品字段只用于第一段。
- 手机号字段不进入模型、不展示、不关联、不埋点。
- 空字段不展示字段标题、空容器或占位符。
- 关注点全字段去重沿用旧设计。
- 关注点去重键继续包含 `label`、`focus`、`satisfaction`、`satis_cate`、`satis_support`、`quote`、`competitor`、`compet_desc`、`compet_sum`。
- 同一关注点但 quote 不同，必须保留。
- 同一 quote 但 `focus` 不同，必须保留。
- 同一完整组合仅 `etl_time` 不同时，保留最新版本。

## 10. 锚点 ID 与交互合同
- 第二部分按钮定位第三部分的 `label` 分组容器。
- 锚点粒度固定为 `satisfactionGroup + label`。
- 锚点 ID 必须由稳定编码生成，禁止依赖数组 index。
- 推荐 ID 结构：`invite-insight-group-${encode(rating)}-${encode(label)}`。
- `encode` 可使用 `encodeURIComponent` 或等价稳定编码。
- `rating` 使用归一后的满意度组展示值。
- `label` 使用清洗后的 q31 大类原文。
- 同一 `rating + label` 在第二部分和第三部分必须生成同一个目标 ID。
- 第三部分空 `label` 分组可使用“未分类”生成稳定 ID。
- 第二部分不得为“未分类”生成按钮。
- 锚点目标应设置在第三部分 `label` 分组容器上，不是单条证据卡。
- 目标容器必须可程序化 focus，可用 `tabIndex={-1}` 或等效能力。
- 目标容器应设置 `scroll-margin-top`，避开 sticky Tab 和抽屉顶部。
- 滚动行为使用 smooth。
- 滚动后焦点进入目标分组容器。
- 目标不存在时，点击不报错、不改变当前数据状态。

## 11. 边界与状态
- q31 查询不变。
- `record.eventId` 精确关联 `IP呼叫ID` / `ipcall_id` 不变。
- lazy load 不变：首次切到客户洞察 Tab 才请求 q31。
- loading、empty、error retry、forbidden、invalid-id 状态不变。
- 快速切换 stale 隔离不变。
- 关闭抽屉后旧请求不得污染下一条记录。
- 有竞品且有关注点：展示提及竞品、客户关注点、关注点证据分组。
- 有竞品但无关注点：展示提及竞品，关注点区域按旧设计空态处理。
- 无竞品但有关注点：隐藏提及竞品，展示客户关注点和关注点证据分组。
- 无竞品且无关注点：展示客户洞察空态。
- 有 `focus` 但 `label` 为空：第二部分不展示；第三部分归入未分类并保留证据。
- 同 `label` 跨满意度：第二部分按满意度分别展示；点击分别定位到不同分组。

## 12. 视觉
- 视觉完全复用试驾客户洞察。
- 卡片外观、圆角、边框、背景、阴影复用试驾。
- 模块间距、组内间距、证据卡密度复用试驾。
- 满意度颜色复用试驾：不满意、满意、中性、其他/未评级。
- chip 形态、hover、focus、active 复用试驾。
- quote 气泡颜色、布局、间距和说话人标识复用试驾。
- 反馈态样式复用 `DriveDetailFeedback`。
- 窄侧栏布局复用当前 drive-detail 规则。
- 430px 宽度下不得出现横向溢出。
- 不得新增邀约专属视觉语言。

## 13. 组件影响范围
- 允许修改 `InviteInsightPanel` 的信息结构和锚点定位。
- 允许调整邀约客户洞察 normalize 输出，以支持 `rating + label` 稳定分组。
- 允许补充局部样式，以满足分组锚点、scroll-margin 和 430px 响应式。
- 允许复用或抽取不带业务语义的展示原语。
- 不得改试驾数据查询、试驾 ID 校验和试驾三表请求。
- 不得把试驾 `receive_id` 逻辑带入邀约。
- 不得把邀约 q31 字段合同带入试驾。
- 不得修改明细清单、全局筛选、负向邀约口径、GIO 埋点口径。

## 14. 验收测试
- 有竞品：显示“提及竞品”，每个三字段组合一张卡。
- 无竞品：不显示“提及竞品”标题和空壳。
- 竞品重复：`competitor + compet_desc + compet_sum` 完全一致只展示一次。
- 第二部分文本：不得出现任何 `focus` 文本。
- 第二部分去重：同满意度同 `label` 只出现一次。
- 跨满意度：同 `label` 在不满意和满意下分别出现。
- 点击：第二部分 `label` 定位到第三部分对应 `rating + label` 分组。
- 多细类：同大类下多个 `focus` 全部可见。
- 空 `label`：第二部分不生成标签，第三部分显示未分类并保留证据。
- 键盘：Tab 可聚焦 chip，Enter 和 Space 可跳转。
- 焦点：跳转后目标分组获得焦点。
- 滚动：目标分组不被 sticky Tab 遮挡。
- 430px：chip、长 label、长 quote、竞品描述无横向溢出。
- 状态：loading、empty、error retry、forbidden、invalid-id、stale 隔离均保持可验证。
- 试驾回归：试驾客户洞察仍按 `rating + primaryLabel` 跳转，试驾四 Tab 和三表请求不变。

## 15. 迁移与回归
- 本变更可在邀约客户洞察内部迁移，不需要数据迁移。
- 旧的单条 `focus` 锚点应退出第二部分点击合同。
- 第三部分可以保留单条证据卡结构，但第二部分不得再定位到单条卡。
- 如已有测试断言“点击 focus 跳单条证据”，应改为“点击 label 跳 rating + label 分组”。
- Mock 数据应补充同 label 多 focus、跨满意度同 label、空 label 有 focus、有竞品无关注点、无竞品有关注点。
- 实现后必须跑邀约客户洞察相关单元测试。
- 实现后必须做试驾客户洞察视觉和交互回归。
- 实现后必须做 430px 窄侧栏截图或等效验证。
- 实现后必须确认 q31 查询、eventId 关联、lazy load、retry 和 stale 隔离无变化。

## 16. 自检结论
- 本文件只覆盖邀约客户洞察大类导航定向变更。
- 本文件明确拒绝跳第一条细类和新增目录导航。
- 本文件明确采用试驾大类分组锚点。
- 本文件明确第二部分只展示 q31 大类 `label`，空 `label` 不用 `focus` 兜底。
- 本文件明确第三部分保留全部 `focus` 证据。
- 本文件明确锚点 ID 由 `rating + label` 稳定编码生成。
- 本文件明确不改试驾。
