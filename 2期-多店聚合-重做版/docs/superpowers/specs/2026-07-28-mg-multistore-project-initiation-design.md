# MG 多店聚合销售诊断工作台立项材料

## 3.1 背景介绍

随着 MG 经销商网络覆盖全国 7 个大区、466 家有效经销商，销售经营管理已从“看一家门店的业绩”转向“跨区域、跨层级管理多家门店”。

总部、大区、小区、销售总监、投资人面对同一套销售经营数据，但关注点不同：

1. 总部关注全国 MG 经营目标完成情况、区域结构差异和重点问题分布。
2. 大区关注所辖区域内小区与门店的目标达成、排名变化和过程短板。
3. 小区关注辖区门店的销售结果、漏斗表现和具体问题对象。
4. 销售总监关注负责范围内的目标进度、销售过程卡点和门店改进动作。
5. 投资人关注所辖门店的经营表现、问题门店和后续跟进行动。

当前多店管理需要回答四个核心问题：

1. 目标完成：订单、零售、交付等经营目标完成得怎么样。
2. 销售漏斗：线索、到店、试驾、订单之间的转化卡在哪里。
3. 问题集中：问题集中在哪些组织、门店、车型或过程环节。
4. 下一步行动：针对问题对象下一步应该采取什么行动。

这些问题背后的数据分散在销售结果、经营目标、邀约、试驾、打铁运营、经销商组织等数据源中。现有单店诊断已经能够支持单家门店的深度复盘，但缺少面向总部、大区、小区、销售总监、投资人的多店聚合视角，无法把多层级组织、经营结果、销售过程和问题对象统一串起来。

因此，本项目建设 MG 多店聚合销售诊断工作台，形成从多层级经营管理出发的统一入口，串联“经营目标—销售结果—过程表现—问题诊断—行动建议—任务生成”。

## 3.2 建设方案

MG 多店聚合销售诊断工作台以多层级经营诊断为主线，先解决不同管理角色在同一口径下看目标、看结果、看过程、找问题、生成行动的问题。数据整合作为底层基础，Agent 诊断、行动建议和任务生成作为顶层规划。

当前建设方案确认到任务生成为止。任务派发渠道、责任人规则、审批机制、流转状态和执行回流由后续方案确定，本文不写成已确定能力。

### 3.2.1 业务数据架构

1. 组织权限层

   组织权限层以 MG 主数据为基础，承接“总部—大区—小区—门店”的组织层级，并适配总部、大区、小区、销售总监、投资人五类角色。该层需要结合罗盘权限，控制不同用户进入工作台后的可见组织范围、门店范围和下钻路径。

   组织权限层同时承担全局筛选联动能力，包括日期、品牌、区域、门店、车系等筛选项。用户调整筛选条件后，经营结果、销售过程、问题诊断和行动建议需要在同一范围内联动。

2. 经营结果层

   经营结果层承接订单、零售、交付等销售结果，以及订单目标、零售目标等经营目标。核心指标包括目标达成率、时间进度、三级排名和贡献占比。

   三级排名用于支持总部看大区、大区看小区、小区看门店；贡献占比用于判断不同组织或门店对当前范围经营结果的贡献。该层后续可扩展专项经营目标，但专项目标的具体范围和口径由后续方案确定。

3. 销售过程层

   销售过程层围绕“线索—到店—试驾—订单”的销售漏斗展开，重点关注线索到店率、到店试驾率、试驾订单率、线索订单率四个转化率。

   过程诊断需要支持当前、上月同期、上周同期三类周期对比，并结合邀约、试驾、打铁运营数据识别过程问题。该层用于回答销售漏斗卡在哪里，而不是只展示最终经营结果。

4. 问题诊断层

   问题诊断层围绕目标未达、进度落后、漏斗断点三类问题展开，定位问题集中在哪些组织、门店、车型或过程环节。

   该层需要输出主问题和结果断点，并支持逐级下钻：从总部到大区，从大区到小区，从小区到门店，再从门店跳转到单店诊断。多店工作台负责定位问题对象和主断点，单店诊断承接门店级深度复盘。

5. 行动任务层

   行动任务层由 Agent 汇总经营结果、过程表现和问题诊断证据，形成诊断结论、行动建议，并生成待跟进任务。

   当前范围只确认 Agent 诊断、行动建议和任务生成。任务派发渠道、责任人、审批、流转、回流规则均由后续方案确定；飞书任务或飞书消息只是未来可能承接方向，不在本文中写成已确定方案。

### 3.2.2 看板功能设计

| 层级 | 看板模块 | 主要内容 | 适配与下钻 |
|---|---|---|---|
| L0 | 经营总览 | 逐项展示订单、交付率、零售、线索到店率、到店试驾率、试驾订单率、线索订单率；展示目标达成和时间进度。 | 作为总部、大区、小区、销售总监、投资人的统一入口，先判断当前范围经营状态。 |
| L1 | 组织对标 | 总部看大区、大区看小区、小区看门店；展示订单、零售目标、达成率、同级排名、贡献占比。 | 用同一口径识别同级组织差异，并支持继续下钻到下一级组织或门店。 |
| L2 | 过程诊断 | 展示销售漏斗、邀约问题率、试驾接待问题率、打铁运营；支持当前、上月同期、上周同期三周期对比。 | 用于定位销售过程卡点，承接 L0/L1 暴露的经营问题。 |
| L3 | 门店穿透 | 展示门店销售结果、漏斗表现、主问题、结果断点，并支持跳转单店诊断。 | 多店工作台定位问题门店，单店诊断承接单店深度复盘。 |
| L4 | Agent 行动 | 输出诊断结论、行动建议、待跟进任务。 | 当前只到生成任务；派发渠道、责任人、审批、流转、回流由后续方案确定。 |

五类角色适配规则如下：

1. 总部：默认查看全国 MG 范围，重点看 7 个大区的目标达成、同级排名、贡献占比和问题分布。
2. 大区：默认查看所属大区，重点看辖区小区之间的经营差异、过程断点和重点问题对象。
3. 小区：默认查看所属小区，重点看辖区门店的目标达成、漏斗表现、主问题和结果断点。
4. 销售总监：默认查看负责范围，重点看目标进度、销售漏斗卡点和需要推动的门店行动。
5. 投资人：默认查看所辖门店，重点看门店销售结果、过程问题、诊断结论和待跟进任务。

## 3.3 业务价值

1. 数据整合价值

   - 将销售结果、经营目标、邀约、试驾、打铁运营、经销商组织数据放到同一条经营诊断主线中。
   - 统一 MG 多店有效经销商范围，减少不同看板、不同角色之间的口径偏差。
   - 支持日期、品牌、区域、门店、车系等筛选条件联动，保证结果、过程、诊断和行动在同一范围内分析。
   - 为后续 Agent 诊断、行动建议和任务生成提供可追溯的数据基础。

2. 管理提效价值

   - 总部、大区、小区、销售总监、投资人使用同一入口看经营目标、销售结果和过程表现。
   - 管理者可以按“总部—大区—小区—门店”逐级定位问题对象。
   - 同级排名和贡献占比帮助识别重点组织、重点门店和重点经营差异。
   - L0 到 L3 的下钻路径让管理动作从看总览进入看对标、看过程、看门店。

3. 诊断行动价值

   - 从目标未达、进度落后、漏斗断点识别主问题。
   - 将销售过程中的邀约、试驾、打铁运营问题与经营结果关联起来。
   - Agent 汇总证据，输出诊断结论和行动建议。
   - 在行动建议基础上生成待跟进任务，为后续任务派发、执行流转和结果回流预留承接位置。

本文不承诺未经验证的效果数字。任务派发、任务流转和执行回流由后续方案确定。
