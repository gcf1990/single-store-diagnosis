# MG 多店聚合经营诊断工作台立项设计

## 4.1 背景

随着 MG 网络覆盖 7 个大区、466 家有效经销商，管理方式已经从单店看业绩，转向跨区域、跨层级的多店经营管理。总部、大区、小区、销售总监、投资人关注的不是同一张表，而是同一套经营事实在不同管理半径下的拆解：总部看整体目标与结构性风险，大区和小区看区域对标与问题门店，销售总监看负责范围内的过程卡点，投资人看所辖门店的经营表现和改善方向。

当前多店管理需要回答四个核心问题：

1. 目标完成得怎么样。
2. 销售漏斗卡在哪里。
3. 问题集中在哪些组织、门店、车型或过程环节。
4. 下一步应该采取什么行动。

这些问题背后的数据分散在销售、目标、邀约、试驾、打铁、组织等数据集中。现有单店诊断已经能够支持门店级深度复盘，但缺少面向多层级管理的聚合视角，无法把组织层级、经营结果、销售过程、问题诊断和行动建议串成一条连续的管理主线。

本项目建设 MG 多店聚合经营诊断工作台，主叙事采用“多层级经营诊断主线”。数据整合作为底层基础，Agent 诊断、行动建议和任务生成作为顶层规划，目标是把经营目标、销售结果、过程表现、问题诊断、行动建议、任务生成串起来，让不同管理角色在同一入口内完成从看结果到找原因、再到形成行动的闭环。

## 4.2 建设蓝图

工作台围绕 MG 多店经营管理设计，不扩展到其他品牌。第一版服务总部、大区、小区、销售总监、投资人五类角色，围绕同一套 MG 有效经销商组织范围，提供从经营总览到组织对标、过程诊断、门店穿透、Agent 行动的分层能力。

建设蓝图的核心原则是：先保证经营诊断主线清楚，再逐步补齐行动承接能力。当前蓝图确认到“生成任务”为止，任务派发渠道、责任人规则、审批机制、流转状态、执行回流方案均由后续方案确定，本文不将其写成已确定能力。

### 4.2.1 分层架构

1. 组织权限层

   组织权限层定义用户能看哪些组织范围、门店范围和管理层级。它承担多角色适配的基础能力：总部看全网，大区看所属大区，小区看所属小区，销售总监看负责范围，投资人看所辖门店。该层需要保证不同角色进入工作台后看到的是同一套口径下的授权范围，而不是各自维护一套孤立数据。

2. 经营结果层

   经营结果层回答“目标完成得怎么样”。它围绕销量、订单、目标、达成、缺口等经营结果指标，承接 L0 经营总览和 L1 组织对标。该层不只展示总量，还要支持按组织层级拆解，让管理者知道问题是整体性偏差、区域性偏差，还是集中在少数门店。

3. 销售过程层

   销售过程层回答“销售漏斗卡在哪里”。它整合邀约、试驾、打铁等过程数据，支持从经营结果下钻到过程环节，识别线索触达、邀约、到店、试驾、成交等链路中的主要卡点。该层是从结果管理转向过程管理的关键，不替代单店诊断，而是把多店范围内的过程异常先聚合出来。

4. 问题诊断层

   问题诊断层回答“问题对象是谁、问题原因可能是什么”。它面向组织、门店、车型和过程环节进行归因提示，并支持从多店聚合视角穿透到单店诊断。该层需要把“哪里差”和“为什么差”连接起来，避免工作台只停留在指标罗列。

5. 行动任务层

   行动任务层回答“下一步做什么”。蓝图包含 Agent 诊断、行动建议和任务生成：Agent 基于经营结果、过程表现和问题诊断生成行动建议，并进一步生成任务草案。当前范围只确认到生成任务，后续是否接入飞书任务、飞书消息或其他承接渠道，以及派发、责任人、审批、流转、回流规则，均由后续方案确定。

### 4.2.2 功能层级

1. L0 经营总览

   L0 是工作台首页视角，提供 MG 多店经营的整体判断入口。经营总览聚焦 7 个核心指标，用于让总部和各级管理者先看到当前范围内的目标完成、销售结果和关键缺口。L0 不承担细节解释，而是负责快速暴露经营状态和需要下钻的方向。

2. L1 组织对标

   L1 支持总部、大区、小区、销售总监、投资人按管理半径进行组织对标。它用于比较不同组织范围的经营表现，识别领先、落后和异常波动对象。组织对标需要沿用同一套有效经销商口径，避免因组织范围不一致导致对比失真。

3. L2 过程诊断

   L2 承接 L0 和 L1 暴露的问题，进入销售过程层拆解。它围绕邀约、试驾、打铁等过程环节，展示不同组织或门店在销售漏斗中的主要卡点，帮助管理者从“结果没达成”进一步定位到“过程哪里断了”。

4. L3 门店穿透

   L3 支持从多店聚合视角穿透到具体门店，并跳转单店诊断。多店工作台负责发现问题对象和排序优先级，单店诊断负责承接门店级深度复盘。两者边界清楚：多店不重复建设完整单店复盘，单店不承担跨组织聚合管理。

5. L4 Agent 行动

   L4 是蓝图中的顶层能力，包含 Agent 诊断、行动建议和任务生成。Agent 基于上层指标、过程和诊断结果，形成可操作的建议，并生成任务草案。当前不定义任务派发渠道、责任人规则、审批机制、流转状态和执行回流，这些由后续方案确定。

6. 多角色适配规则

   工作台第一版服务总部、大区、小区、销售总监、投资人。多角色适配不意味着为每个角色重做一套页面，而是在统一诊断主线下，根据角色权限、组织范围和管理目标调整默认视角、可见范围和下钻路径。总部优先看全网和区域结构，大区、小区优先看辖区对标和问题门店，销售总监优先看负责范围内的过程卡点，投资人优先看所辖门店经营表现和行动建议。

## 4.3 项目价值

1. 数据整合价值

   项目把销售、目标、邀约、试驾、打铁、组织等数据集中到同一条经营诊断主线上，让多店管理不再依赖分散报表和人工拼接。数据整合不是最终价值，而是支撑经营结果、过程诊断和行动生成的基础。

2. 管理提效价值

   项目为总部、大区、小区、销售总监、投资人提供统一入口和分层下钻路径，使管理者能够围绕同一套口径看目标、看对标、看过程、看问题对象。本文不承诺未经验证的节省时间、效率百分比或上线效果；第一版价值以管理路径是否连贯、角色视角是否清楚、问题是否能被定位为验收重点。

3. 诊断行动价值

   项目从“看数”推进到“诊断”和“行动”。多店工作台先发现经营结果和过程异常，再通过问题诊断层定位对象和可能原因，最后由 Agent 生成行动建议和任务草案。任务后续如何派发、流转和回流不在当前确认范围内，需由后续方案确定。
