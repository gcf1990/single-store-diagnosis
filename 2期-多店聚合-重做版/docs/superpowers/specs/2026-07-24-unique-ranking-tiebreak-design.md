# 订单/零售稳定唯一排名设计

**状态：** 仅设计，待用户审阅；审阅通过后才进入 Product-Spec / DEV-PLAN / 代码实施
**日期：** 2026-07-24
**范围：** `multi-store-super-app/` PC 销售概览中的订单排名、零售排名
**事实源：** 用户已确认口径；当前实现见 `multi-store-super-app/organization-view.js` 的 `rankRows()`

## 1. 背景 / 问题

当前 `rankRows()` 使用竞争排名：

- 先按主指标降序排序。
- 主指标相同再按组织代码升序排序。
- 但同值行复用上一名次，因此会出现 `1/3, 1/3, 3/3`。

在 53 个对象的列表中，如果末尾多家订单数或零售数相同，最后一组会共用同一个名次，页面可能显示到 `46/53`，业务用户会误解为“只有 46 名”或“后 7 家没有独立排序”。

本次目标不是重新定义比较集合，而是把同值组从“并列名次”改为“稳定拆分后的唯一名次”，让页面始终可落到 `n/n`。

## 2. 结论

订单排名、零售排名统一改为稳定唯一排名：

- 主指标降序：订单排名按订单数降序；零售排名按零售数降序。
- 主指标同值时，按组织代码升序稳定拆分。
- 每一行都有唯一名次，展示仍为 `排名 x/y`。
- 不展示并列、不展示组织代码、不展示末位人数、不新增额外解释。
- 全 0 或全同值时同样稳定输出 `1/n ... n/n`。

示例：

| 组织代码 | 订单数 | 旧竞争排名 | 新唯一排名 |
|---|---:|---:|---:|
| S001 | 8 | 1/5 | 1/5 |
| S002 | 5 | 2/5 | 2/5 |
| S003 | 0 | 3/5 | 3/5 |
| S004 | 0 | 3/5 | 4/5 |
| S005 | 0 | 3/5 | 5/5 |

## 3. 确认的决策

- 大区、小区、经销商三级都适用唯一排名。
- 订单、零售两个主指标都适用唯一排名。
- 比较集合和分母不变，只改同值名次分配。
- 排序规则使用已有稳定排序基础：`主指标降序 + 组织代码升序`。
- UI 仍只展示 `排名 x/y`，不把拆分依据暴露给用户。
- 占比继续按当前比较集合合计值计算，不受唯一名次改造影响。
- 全国完整性不可证时，大区层排名继续显示 `--`。
- 导出字段和格式不变；导出中的排名值随页面排名一致更新为唯一排名。

## 4. 非目标

本次不做：

- 不新增字段、数据源、SQL 查询、接口参数或前端状态。
- 不引入随机数、时间戳、数组原始顺序等不稳定拆分依据。
- 不展示“并列第 N 名”、组织代码、同值说明、末位人数或 tooltip 补充说明。
- 不改变订单数、零售数、订单占比、零售占比公式。
- 不改变车系筛选、权限白名单、组织筛选、日期筛选或数据查询链路。
- 不改变动态诊断、主问题、结果断点、全国完整性证据口径。
- 不改变分页、行序、导出列名、导出文件格式或发布配置。

## 5. 适用范围

### 5.1 组织层级

| 层级 | 比较集合 | 唯一排名规则 |
|---|---|---|
| 大区层 | 全国完整大区集合；全国完整性不可证时不排名 | 主指标降序，同值按大区代码升序 |
| 小区层 | 当前大区内小区集合 | 主指标降序，同值按小区代码升序 |
| 经销商层 | 当前小区、投资人 portfolio、扁平模式或具体筛选后的经销商集合 | 主指标降序，同值按经销商代码升序 |

### 5.2 已确认保持不变的比较集合

- 默认层级：沿用当前 `comparisonKey()` 分组逻辑。
- 投资人 portfolio：继续使用 `rankScope="portfolio"` 下的当前有效门店集合。
- 当前范围全部经销商扁平模式：继续按当前扁平经销商集合统一排名。
- `drillPath`：继续先按当前下钻路径收窄，再在收窄后的 peerRows 中排名。
- 具体门店收窄：如果只剩 1 家，仍显示 `1/1`。

## 6. 算法伪代码

以下为伪代码，只表达口径，不是实现代码：

```text
function stableUniqueRank(rows, metric, level, nationalComplete, rankScope):
  if level is area and nationalComplete is false:
    return empty rank map

  groups = group rows by existing comparison key(level, rankScope)

  for each group in groups:
    rankedRows = sort group by:
      1. current[metric] descending
      2. organization code ascending

    denominatorValue = sum current[metric] in rankedRows
    totalCount = count rankedRows

    for each row with zero-based index in rankedRows:
      rankValue = index + 1
      rankText = rankValue + "/" + totalCount
      share = denominatorValue == 0 ? null-or-existing-rate-empty-semantic : current[metric] / denominatorValue
      save rankText, rankValue, totalCount, metricValue, share by row code

  return rank map
```

实施要点：

- 删除“同值复用上一名次”的逻辑。
- 保留现有 `rankedRows` 排序中的组织代码升序 tie-break。
- 保留 `totalCount` 作为分母人数，不改为指标合计。
- 保留 `share` 的现有计算语义；当分母为 0 时继续沿用当前 `rate()` 空值语义，不为排名新增错误态。

## 7. 数据流和 UI 展示

数据流保持现状：

1. 上游品牌、日期、区域、小区、经销商、车系、罗盘权限、有效经销商白名单共同得到已过滤销售事实集合。
2. `buildViewRows()` 按当前展示层级和 `drillPath` 聚合 `visibleRows`。
3. `buildViewRows()` 对 `peerRows` 分别计算订单排名和零售排名。
4. 页面行使用 `orderRank`、`retailRank` 渲染销售概览排名槽。
5. 导出复用页面当前行数据，字段名和 CSV 格式不变。

UI 保持现状：

- 订单表现、零售表现中仍显示 `排名 x/y`。
- 表头、列名、顺序、字号、颜色、tooltip、空态文案不因本次改动变化。
- 不展示组织代码，即使组织代码是同值拆分依据。
- 当同值末组存在时，末组可依次显示 `46/53 ... 53/53`。

## 8. 边界 / 错误语义

| 场景 | 预期 |
|---|---|
| 主指标同值 | 按组织代码升序拆分为连续唯一名次 |
| 全部主指标为 0 | 仍按组织代码升序输出 `1/n ... n/n` |
| 只有 1 个对象 | 输出 `1/1` |
| 组织代码缺失或为空 | 组织代码是当前行身份键且应唯一；本次不新增名称、随机数或输入顺序回退，也不修复上游缺失代码问题；对已有合法行保持排序稳定 |
| 全国完整性不可证的大区层 | 继续不输出伪全国排名，显示 `--` |
| 指标值为空、非数值或缺失 | 沿用现有 `number()` 归一化语义，不新增错误态 |
| 订单/零售分母合计为 0 | 排名仍唯一；占比继续沿用现有空值或 0 分母语义 |
| 车系筛选后同值 | 在筛选后的 peerRows 内稳定拆分，不回退全部车系 |
| 权限或白名单收窄 | 只在可见且有效的集合内排名，不补入不可见对象 |

| AC-U003 | 小区层订单/零售排名：同一大区内多个小区主指标同值时，按小区代码升序拆分，订单和零售分别独立计算。 |
| AC-U004 | 经销商层订单/零售排名：同一比较集合内多个经销商主指标同值时，按经销商代码升序拆分。 |
| AC-U005 | 53 对象末尾同值：页面可从 `46/53` 连续展示到 `53/53`，不再停留在同一个名次。 |
| AC-U006 | 投资人 portfolio：投资人门店层继续按当前有效 portfolio 集合排名，同值按经销商代码拆分，不按所属小区拆分。 |
| AC-U007 | 全部经销商扁平模式：全国、大区或当前下钻路径扁平后，订单/零售排名在当前扁平集合内唯一排名，占比分母不变。 |
| AC-U008 | 单店收窄：上游具体门店筛选或当前集合仅 1 家时，订单排名和零售排名均为 `1/1`，占比仍为当前语义。 |
| AC-U009 | 全国不完整：大区层全国完整性不可证时，订单排名、零售排名继续显示 `--`，不因唯一排名改造绕过完整性门禁。 |
| AC-U010 | 稳定性：对组织代码合法且唯一的行，相同输入多次计算、不同浏览器刷新、数组输入顺序变化后，只要组织代码和指标值相同，排名结果一致。 |
| AC-U011 | 全 0：订单或零售全为 0 时仍输出稳定 `1/n ... n/n`，不展示并列或错误文案。 |
| AC-U012 | 导出：导出字段名、列顺序、文件格式不变；订单排名和零售排名值与页面唯一排名一致。 |
| AC-U013 | 非目标回归：车系、权限、组织筛选、日期、数据查询、动态诊断、占比、分页、行序、目标字段和打铁指标均不因本次改动变化。 |
