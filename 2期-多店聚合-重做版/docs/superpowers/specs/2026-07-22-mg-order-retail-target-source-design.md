## 2. 新目标数据合同

| 字段 | 用途 | 规则 |
|---|---|---|
| `目标日期` | 目标月份 | 取所在自然月 1 日作为目标月份 |
| `dealer_code` | 目标门店键 | 对接销售事实 `一级经销商代码`，并与有效经销商维表取交集 |
| `车系` | 目标车系键 | 对接销售事实 `汇报车系名称`，随车系多选集合过滤 |
| `总订单目标` | 订单目标分母 | 允许 0；负数、非数字剔除；冲突键作废并审计 |
| `总零售目标` | 零售目标分母 | 允许 0；负数、非数字剔除；冲突键作废并审计 |

品牌固定补为 `MG`。组织归属只取现有有效经销商维表 `a310ff90fddff4b6283841c6`；不得信任新目标表里的 `area/city_name/rfs_name/mac_name` 等组织字段。

已查证并纳入当前测试审计的样本：2026-07 新表 1542 行，订单目标合计 22578，零售目标合计 18580，无重复冲突；5 条目标记录未命中现有有效经销商维表，当前实现必须排除并保留 QA 缺口。

## 3. 计算口径

目标自然键：`目标月份 + MG + dealer_code + 车系`。

订单目标达成：
- 分母：同自然键去重后的 `总订单目标`
- 分子：销售宽表按自然月 + `品牌名称=MG` + `一级经销商代码` + `汇报车系名称` 聚合 `当日订单数（首触）`
- 达成率：订单目标口径实际 / 总订单目标

零售目标达成：
- 分母：同自然键去重后的 `总零售目标`
- 分子：销售宽表按同键聚合 `当日零售数`
- 达成率：零售目标口径实际 / 总零售目标

不得复用 `salesAggregateSql` 计算目标实际，因为该聚合结果已丢失车系维度。目标链路也不得改写主订单、主零售、漏斗、排名、占比和过程指标的用户筛选日期口径。

## 4. 范围与降级

| 场景 | 目标行为 | 主销售链路 |
|---|---|---|
| MG + 单一自然月 + 有目标 | 展示订单/零售目标和达成 | 不变 |
| MG + 单一自然月 + 无目标 | 隐藏标题摘要，表格目标空槽 | 不变 |
| 跨月或未来月 | `invalid_range`，隐藏两类目标 | 不变 |
| 非 MG 品牌 | 隐藏两类目标，不跨品牌复用 | 不变 |
| 请求失败/无权限/业务码失败 | 仅目标位置显示暂不可用 | 不变 |
| 目标有实际无 | 生成目标门店行，实际为 0 | 不变 |
| 实际有目标无 | 进入主订单/主零售，进入未配置目标实际审计 | 不变 |
| 目标不在有效经销商维表 | 排除展示并计入白名单缺口 | 不变 |

## 5. 展示规则

顶部“销售指标”标题摘要：

`订单目标：{订单目标}　订单达成：{订单达成率}　零售目标：{零售目标}　零售达成：{零售达成率}`

卡片规则不变：订单、交付率、零售和四张过程卡只展示指标值、月环比、周环比；卡内不得出现目标文本、目标空槽、目标提示或目标骨架。

销售概览表：
- 订单表现：`月目标｜目标达成 / 排名｜占比`
- 零售表现：`月目标｜目标达成 / 排名｜占比`
- 排名和占比继续使用当前动态组织口径，文案统一为“排名”“占比”。
