## 1. 背景与结论

MG 07 小订期是固定经营窗口，不应被现有销售总览的销售日期、车系筛选和销售组织下钻牵着走。当前项目已有销售事实源、组织权限、PC 分层下钻和多模块并行加载能力；本轮新增一个独立“MG 07小订战报”，专门展示小订目标、累计小订、目标达成、时间进度和当前层级落后对象。

采用已选 A 方案：摘要常驻、达成表现按需展开/收起。

- 常驻摘要固定展示四项经营指标：`小订目标`、`累计小订`、`目标达成`、`时间进度`；第五项按当前展示层级动态显示 `落后大区`、`落后小区`、`落后门店` 或单门店 `自身进度状态`。
- `小订达成表现`默认收起，用户需要定位落后对象时再展开；展开后按应达缺口排序展示当前层级对象。
- 展开状态只在本会话保留；重新进入页面默认收起。
- 战报下钻独立于现有销售概览/过程分析/打铁指标下钻，不跟随销售日期筛选、车系筛选或销售下钻状态，但继承当前观远用户组织权限。

## 2. 明确范围与非目标

## 3. 信息架构与精确文案

模块标题固定文案：`MG 07小订战报`

摘要区固定四项经营指标，顺序不可调整：

1. `小订目标`
2. `累计小订`
3. `目标达成`
4. `时间进度`

四项经营指标右侧固定保留第五个动态层级位：

| 当前战报层级 | label | value | 单位 |
|---|---|---|---|
| 总部看大区 | `落后大区` | 当前可见大区中 `gap_to_expected > 0` 的对象数量 | 个 |
| 大区看小区 | `落后小区` | 当前可见小区中 `gap_to_expected > 0` 的对象数量 | 个 |
| 小区看门店 | `落后门店` | 当前可见门店中 `gap_to_expected > 0` 的对象数量 | 个 |
| 单门店 | `自身进度状态` | `领先` / `落后` / `零目标` / `数据暂不可用` | 无 |

状态文案固定三种：`小订即将开始`、`小订进行中`、`小订已结束`。

`层级动态落后对象`仅指上表第五动态位，不替换具体对象名称；对象名称只在展开后的 `小订达成表现` 列表中展示。

展开区标题固定文案：`小订达成表现`

展开/收起交互：

- 默认收起，仅展示摘要和展开入口；展开后显示当前层级对象列表，并把入口文案切换为收起状态。
- 展开状态保存在当前浏览会话内；同一页面会话内切换战报下钻层级、返回上一级、刷新数据时保留用户最近一次展开/收起选择；重新进入子应用、刷新浏览器或重新打开父应用后默认收起。

## 7. 计算公式与异常规则

基础字段：

- `target_total`：当前权限与当前战报层级范围内，目标源 `MG07小订目标` 求和。
- `actual_small_order_all`：当前权限与当前战报层级范围内，所有 MG 07 一级经销商的 `当日首触小订数` 求和，用于页面 `累计小订`。
- `achievement_actual`：当前权限与当前战报层级范围内，命中 403 家目标自然键的 `当日首触小订数` 求和；零目标但已配置的目标行仍属于目标集合，用于上级组织汇总。完全未配置目标的实际不进入该字段。
- `retained_small_order`：同范围 `当日首触留存小订数` 求和。
- `cancelled_small_order`：同范围 `当日首触小订退订数` 求和。
- `data_updated_at`：本次实际结果中 `调度时间` 的最大值。
- `period_progress`：§4 时间进度，取值 `0` 到 `1`。
- `expected_by_time`：`target_total * period_progress`。
- `gap_to_expected`：`max(0, expected_by_time - achievement_actual)`。
- `achievement_rate`：`achievement_actual / target_total`。

展示规则：

- `小订目标`：展示 `target_total`，整数千分位。
- `累计小订`：展示 `actual_small_order_all`，整数千分位。
- `目标达成`：当 `target_total > 0` 时展示百分比，保留 1 位小数，不封顶；当 `target_total = 0` 时展示 `--`。
- `时间进度`：展示 `period_progress * 100%`，保留 1 位小数。
- 第五动态位：前三层 value 为当前下一层 `gap_to_expected > 0` 的对象数量，单位统一为 `个`；单门店 value 为 `领先`、`落后`、`零目标` 或 `数据暂不可用`。
- 摘要副标题必须显示 `data_updated_at` 对应的真实数据更新时间；实际未查询或失败时不显示虚假时间。

目标为 0：

- 目标行保留，计入 403 家和零目标门店审计。
- `目标达成`展示 `--`，不做除零。
- `expected_by_time = 0`，`gap_to_expected = 0`。
- 若实际小订大于 0，进入 `zero_target_actual` 审计；该实际计入 `累计小订` 和上级组织 `achievement_actual`，但该零目标门店自身 `目标达成`仍展示 `--`。

目标有实际无：

- 生成目标对象行。
- `actual_small_order_all = 0`、`achievement_actual = 0`，`achievement_rate = 0.0%`。
- 按时间进度计算 `gap_to_expected`，进入达成表现列表。

实际有、目标无：

- 进入 `unconfigured_actual` 审计。
- 实际计入 `累计小订`，但不并入 `小订目标`、`achievement_actual`、`目标达成`和默认达成表现列表。
- 可在 QA 审计输出中列出一级经销商代码、实际小订数和来源日期范围；正式页面默认不展示，避免把无目标门店混入战报分母。

## 8. 层级合同与独立下钻

战报使用独立视图状态，例如 `smallOrderViewState`，不得复用或改写现有销售表现区 `organization.viewLevel/drillPath`。

入口层级：

| 用户/上游范围 | 战报首层展示 | 下钻路径 |
|---|---|---|
| 总部看全部 | 大区 | 大区 -> 小区 -> 门店 |
| 总部收窄到具体大区 | 小区 | 小区 -> 门店 |
| 总部收窄到具体小区或门店 | 门店 | 门店 |
| 大区用户 | 小区 | 小区 -> 门店 |
| 小区用户 | 门店 | 门店 |
| 单门店用户 | 自身门店 | 无下钻 |

层级文案：

- 总部层列表对象为大区，操作为查看小区。
- 大区层列表对象为小区，操作为查看门店。
- 小区层列表对象为门店，操作为门店行聚焦，不跳单店详情。
- 单门店层只展示自身进度状态，不显示下钻按钮。

独立性规则：

- 战报下钻不改变销售概览、过程分析、打铁指标的当前 Tab、页码、排序、下钻、扁平态或导出范围。
- 销售概览下钻、返回上一级、当前范围全部经销商扁平查看，不改变战报下钻。
- 上游销售日期筛选和车系筛选不作用于战报；战报始终使用固定小订期和固定 `MG 07`。
- 战报必须继承观远登录用户身份、组织权限和行权限；不得通过目标源补出无权限组织。

## 9. 排序与达成表现列表

`小订达成表现`默认排序：

1. 按 `gap_to_expected` 降序。
2. 同值按组织代码升序。

列表最少字段：

| 字段 | 说明 |
|---|---|
| 对象名称 | 大区/小区/门店名称 |
| 对象代码 | 大区/小区/一级经销商代码 |
| 小订目标 | 当前对象目标 |
| 累计小订 | 当前对象实际 |
| 目标达成 | 当前对象达成率 |
| 时间进度 | 同摘要时间进度 |
| 应达缺口 | `gap_to_expected` 四舍五入到整数 |
| 状态 | `领先` / `落后` / `零目标` / `数据暂不可用` |

默认只展示当前层级对象，不跨层混排。总部展开只看大区；进入某大区后展开只看该大区下的小区；进入小区后展开只看门店。

## 10. 技术模块边界

建议新增独立模块，不把逻辑塞入现有销售目标链路：

| 模块 | 职责 |
|---|---|
| `small-order-config` | 读取固定小订期、目标数据集 `dsId`、实际数据集 `dsId`、字段合同 |
| `small-order-api` | 并行读取目标数据和实际 SQL 聚合，返回来源状态和审计 |
| `small-order-model` | 归一目标、归一实际、权限裁剪、组织聚合、计算达成率和应达缺口 |
| `small-order-view` | 渲染摘要、状态、展开列表和独立下钻 |
| `small-order-validation` | 固定样本、日期边界、权限和响应式测试 |

并行加载：

- 主应用完成用户身份与组织权限解析后，战报目标与实际并行请求。
- 战报请求不得阻塞销售事实、车系枚举、销售概览、过程分析或打铁指标渲染。
- 目标请求和实际请求各自有独立状态；任一失败只降级战报对应区域。

请求身份隔离：

- 战报使用独立请求 token，例如 `smallOrderLoadToken`。
- 缓存 key 至少包含：模块名、用户身份摘要、组织权限范围、战报下钻路径、目标 `dsId`、实际 `dsId`、固定小订期、当前统计截止日。
- 不复用销售概览 `vehicleSeries` cache key，不复用月目标 cache key，不让旧战报响应覆盖新战报状态。

失败降级：

| 失败场景 | 页面行为 | 主应用影响 |
|---|---|---|
| 目标配置缺失或目标源失败 | 摘要显示小订目标暂不可用，达成表现不可展开 | 销售/过程/打铁不受影响 |
| 实际源失败 | 保留目标和时间进度，累计小订与目标达成显示数据暂不可用 | 销售/过程/打铁不受影响 |
| 权限失败 | 战报显示暂无该范围数据权限 | 不扩大范围，不反推无权限 |
| 字段缺失或完整性不可证 | 战报显示数据不完整 | 不用 0 或旧缓存伪装成功 |
| 当前权限下目标和实际均为空 | 显示空态，文案为当前范围暂无 MG 07 小订战报数据 | 不等同无权限 |
