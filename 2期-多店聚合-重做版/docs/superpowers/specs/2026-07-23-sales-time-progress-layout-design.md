# PC 销售经营进度条与时间进度布局设计

**状态：** 仅规格设计，待用户审阅后进入 DEV-PLAN  
**日期：** 2026-07-23  
**范围：** `multi-store-super-app/` PC 顶部销售总览布局  
**事实源：** `Product-Spec.md` v1.79 / REQ-013 / AC-227～AC-234

## 1. 结论

采用已批准的方案 A：在“销售指标”和“过程指标”两个并排模块上方新增独立“销售经营进度”条。条内展示 `订单目标 / 订单达成 / 零售目标 / 零售达成 / 时间进度`；两个指标模块内部恢复为仅标题 + 指标卡。

时间进度只显示百分比，公式为 `今天日期序号 / 当月月末日期序号 * 100%`，展示 1 位小数。例如 7 月 23 日为 `23 / 31 = 74.2%`。该指标只表达本月日历进度，使用中性灰蓝，不用绿色或红色，不表达达标。

本轮只定义 PC 顶部布局，不改表格订单/零售表现、过程指标数据口径、筛选、导出或移动端。

## 2. 信息架构

现状结构：

`销售总览标题 + 车系筛选`  
`销售指标模块标题 + 目标摘要 / 销售指标卡`　`过程指标模块标题 / 过程指标卡`

目标结构：

`销售总览标题 + 车系筛选`  
`销售经营进度条：订单目标 / 订单达成 / 零售目标 / 零售达成 / 时间进度`  
`销售指标模块标题 / 销售指标卡`　`过程指标模块标题 / 过程指标卡`

销售指标卡仍为 `订单 / 交付率 / 零售`；过程指标卡仍为 `线索到店率 / 到店试驾率 / 试驾订单率 / 线索订单率`。

## 3. 视觉层级

- “销售经营进度”是模块级辅助信息，层级低于“销售总览”，高于两个指标模块标题。
- 订单目标、零售目标沿用当前目标蓝色语义；订单达成、零售达成沿用当前达成绿色语义。
- 时间进度使用中性灰蓝；不加红绿语义、箭头、达标标签、状态圆点或进度条填充。
- 销售指标和过程指标模块标题不再承载目标摘要，避免标题行挤压和模块单独加高。

## 4. 数据/日期口径

- 订单目标、订单达成、零售目标、零售达成复用 REQ-011 目标链路，不新增数据源、不改目标自然键、不改目标口径实际 SQL。
- 时间进度使用页面运行时当前自然日计算：`dayOfMonth(today) / lastDayOfMonth(today) * 100%`。
- 时间进度展示 1 位小数；每月 1 日显示 `1 / 月末日`，月末显示 `100.0%`。
- 时间进度不使用父应用筛选 `endDate`，不使用目标实际统计窗口，不按工作日修正。

## 5. 响应式/对齐规则

- 经营进度条独立占一行，宽度跟随销售总览内容区。
- 1280px 和 1440px 浅色、深色主题下不得出现页面级新增横向溢出。
- 宽度不足时，只允许经营进度条内部自然换行。
- 下方“销售指标”和“过程指标”两个模块必须同起点、同高、指标卡同水平基线。
- 不允许通过给过程模块加空白占位、给销售模块单独加高、或把时间进度塞回标题行来对齐。

## 6. 状态降级

经营进度条整体继承现有目标摘要降级：

| 场景 | 行为 |
|---|---|
| 单一自然月 MG 且存在有效目标 | 显示 5 项经营进度 |
| 无目标 | 整条隐藏 |
| 跨月、未来月、非 MG | 整条隐藏 |
| 目标请求失败、无权限、业务码失败 | 经营进度条位置显示既有“月目标数据暂不可用”类文案 |
| 目标隐藏或无效 | 不单独显示时间进度 |
