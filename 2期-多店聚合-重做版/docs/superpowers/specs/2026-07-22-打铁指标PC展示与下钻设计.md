## 2. 组件结构

### 2.1 一级表现区

一级表现区仍由标题/范围文案、返回上一级、右侧导出入口和一级 tablist 组成。“打铁指标”只新增第三个一级 Tab，不移动现有控件。v1.77 起，当打铁指标满足当前范围全部经销商条件时，表现区 header 工具区在导出按钮左侧显示同一个“查看所有经销商 / 返回分层查看”入口。

```text
表现区标题 + 范围文案 + 返回上一级
右侧：查看所有经销商/返回分层查看 + 导出入口 + 销售概览 / 过程分析 / 打铁指标
```

### 2.2 打铁指标面板

```text
二级切换：邀约指标 7 | 试驾指标 4
表格：组织列 + 当前组指标列 + 操作列
分页：页面复用当前组织表现区分页；导出不受当前页 15 行限制
```

二级切换使用现有 PC 分段按钮视觉，按钮高度、圆角、边框、激活态、hover、focus 与现有 tab/按钮同源。

扁平态时表格首列为 `经销商名称`，操作列只保留 `门店详情`，标题为 `全部经销商打铁表现`。二级切换仍位于表格上方或左侧的既有位置，切组不得改变扁平状态、页码、范围文案或导出按钮位置。

### 3.3 表头规则

- 每个指标表头必须先读到指标名称，再读到目标提示。
- 目标提示只使用 `目标 xx%`，层级弱于指标名称。
- `首跟通话60s占比` 下方不显示“无目标”、`--`、空破折号或占位文案。
- 目标不参与达标视觉，不产生红绿底色、圆点、达标标签、官方识别状态或综合得分。

## 4. 组织层级与状态机

### 4.1 入口层级

| 用户/上游范围 | 默认 viewLevel | 操作路径 |
|---|---|---|
| 总部 + 全部大区 | 大区 | 大区 → 小区 → 门店 |
| 总部 + 具体大区 | 小区 | 小区 → 门店 |
| 总部 + 具体小区/门店 | 门店 | 门店 |
| 大区角色 + 全部小区 | 小区 | 小区 → 门店 |
| 大区角色 + 具体小区/门店 | 门店 | 门店 |
| 小区角色 | 门店 | 门店 |
| 销售总监 | 门店 | 授权门店 |
| 投资人 | 门店 | 授权门店 |

### 4.2 状态机

```text
entry(viewLevel, drillPath=[])
  ├─ 一级 tab 切换：保留 viewLevel/drillPath/pageIndex/organizationOrder
  ├─ 二级组切换：只改 activeMetricGroup，保留 viewLevel/drillPath/pageIndex/organizationOrder
  ├─ 查看所有经销商：保存 viewLevel/drillPath/pageIndex/activeMetricGroup 快照，派生 effectiveLevel=store
  ├─ 扁平态二级组切换：只改 activeMetricGroup，保留 allDealerMode/effectiveLevel/pageIndex/organizationOrder
  ├─ 返回分层查看：恢复 viewLevel/drillPath/pageIndex/activeMetricGroup 快照
  ├─ 查看小区/查看门店：追加 drillPath，进入下一层
  ├─ 返回上一级：弹出 drillPath，回到上一合法层
  └─ 上游 Query 变化：清空 drillPath，按新有效范围重新自动跳层
```

扁平态下 `查看小区/查看门店` 和面包屑返回不可见且事件不生效；门店行仍可进入“门店详情”。

### 4.3 组织骨架与行序

- “打铁指标”不使用销售 `汇报车系名称`，也不以具体车系筛选后的销售行集作为自身行集。
- “打铁指标”的组织骨架复用无车系 `processBaselineData` / 过程基线有效组织集合；行序沿用 `OrganizationView` 同层级排序规则。
- “共享行序”只要求同一打铁组织骨架内，一级 Tab 切换和邀约/试驾二级切换保持当前 `viewLevel/drillPath`、排序规则和页面分页状态一致；不要求具体车系筛选后销售概览与打铁指标的行数或成员完全一致。
- 扁平态行集是 `上游 URL 筛选 ∩ 罗盘行权限 ∩ 有效经销商白名单 ∩ 当前 drillPath` 内的全部可见经销商；不得新增数据集、不得触发新全量查询、不得用销售行集补齐。

### 4.4 操作列

| 当前层级 | 操作文案 | 行为 |
|---|---|---|
| 大区 | 查看小区 | 进入该大区下的小区列表 |
| 小区 | 查看门店 | 进入该小区下的门店列表 |
| 门店 | 门店详情 | 复用既有单店详情跳转 |

## 5. 数据状态

| 状态 | 展示 |
|---|---|
| 加载中 | 同形骨架 |
| 成功且有值 | 百分比，1 位小数 |
| 真无样本 | `--` |
| 分母有效但分子为 0 | `0.0%` |
| 来源失败、截断、字段缺失或完整性不可证 | `数据不完整` |

六类来源独立记录状态。某一来源失败只影响其对应指标，不清空其他来源已成功指标，不用旧缓存覆盖新组。

## 6. 导出策略

- v2.13 更新：本节继续约束导出入口、导出范围、全量行和行序；历史内部诊断字段清单不再约束当前打铁 CSV 字段。当前打铁 CSV 字段以 `Product-Spec.md` 的 AC-423～AC-427 为准，即一行一个当前组织范围对象，首列为当前前端首列，后续按当前激活二级组指标顺序输出当前值、月环比和周环比宽表列。
- 复用现有 PC 导出入口，不新增第二个导出按钮。
- 当一级 Tab 为“销售概览”或“过程分析”时，既有导出策略不变。
- 当一级 Tab 为“打铁指标”时，导出范围为当前激活二级组、当前 `viewLevel/drillPath` 范围内全部组织行，非仅当前 15 行分页。
- 当一级 Tab 为“打铁指标”且 `allDealerMode=true` 时，导出范围为当前激活二级组、当前扁平范围内全部经销商行，非仅当前 15 行分页。
- 导出行序与页面同一打铁组织骨架排序一致；页面分页只影响屏幕显示，不裁剪导出行集。
- 历史 v1.70/v1.75 内部诊断长表字段至少包含组织层级、组织编码、组织名称、指标分组、指标编码、指标名称、指标值、分子、分母、目标值、目标展示文案、来源状态和完整性；当前 v2.13 业务 CSV 不再输出这些内部诊断字段。
- 导出不输出 `status_value/status_label`，不输出官方识别状态、达标标签或综合得分。

## 7. 响应式与主题

- 1280px 与 1440px PC 视口均需验证浅色、深色主题。
- 页面级不得新增横向溢出；表格区域可复用既有横向滚动容器。
- 组织列和操作列沿用现有 sticky/宽度策略，不能挤压到不可读。
- 表头指标名称允许合理换行；目标提示不可压住指标名称。
- 暗色主题只调整现有 token，不新增紫色、红绿状态底或新品牌色。

## 8. 无障碍

- 一级 tab 与二级切换使用 `role=tablist/tab/tabpanel` 或等价语义。
- `aria-selected`、`aria-controls` 与可见面板一致。
- 键盘左右方向键可在同一 tablist 内切换；Tab 键顺序按视觉顺序进入一级 tab、二级切换、表格、操作列、分页和导出。
- 焦点环清晰可见，不被表格容器裁切。
- 当前激活组不能只靠颜色表达，必须同时通过 `aria-selected=true` 和可见样式表达。
- `数据不完整` 使用可读文本；错误/禁用/当前状态不只靠颜色表达。
