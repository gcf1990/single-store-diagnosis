# 单月自然月目标达成口径设计

**状态：** 已实现，QA PASS
**日期：** 2026-07-21  
**范围：** `multi-store-super-app/` 的 PC 销售总览月目标区域

## 1. 目标

用户可以在单一自然月内自由选择任意日期区间，同时稳定查看该月完整月目标的达成情况；目标达成不再随着所选起止日而改变。跨月查询不展示月目标和目标达成，避免把多个自然月合并为一个难以解释的比例。

## 2. 已确认的业务规则

1. 仅当用户筛选的开始、结束日期属于同一非未来自然月时，展示“月目标、目标达成”。开始日期不再要求为当月 1 日；未来月进入 `invalid_range` 空槽并发起零目标请求。
2. 月目标分母始终读取筛选所在自然月的完整月目标，即当月 1 日至月末的目标数据。
3. 目标口径实际订单分子统一统计为当月 1 日至今天；如所查月份已结束，则统计当月 1 日至该月月末。
4. 顶部订单、交付率、零售、过程指标、销售结果漏斗、排名及占比继续严格使用用户实际筛选日期，不改既有销售口径。
5. 跨月筛选（例如 6/25–7/10）隐藏月目标和目标达成，并保留现有 2×2 版式中的无障碍空槽；不显示提示文案。
6. 既有品牌、大区、小区、门店、车系、行权限、有效经销商白名单均同时作用于目标分母和目标口径实际订单分子。

## 3. 日期窗口设计

### 3.1 原始筛选窗口

`selectedRange` 保持不变，继续供既有销售主链路、环比周同比、漏斗、排名、占比和导出主指标使用。

### 3.2 月目标窗口

新增/调整统一的月目标日期解析结果：

| 条件 | `targetRange` | `targetActualRange` | 页面行为 |
| --- | --- | --- | --- |
| 单月历史查询 | 月初至月末 | 月初至月末 | 展示月目标、目标达成 |
| 单月当前月查询 | 月初至月末 | 月初至今天 | 展示月目标、目标达成 |
| 跨月查询 | 无 | 无 | 隐藏月目标、目标达成 |
| 单月未来月查询 | 无 | 无 | `invalid_range` 空槽与零目标请求 |
| 无效日期 | 无 | 无 | 沿用既有无目标展示 |

其中“今天”取应用运行时本地日期；目标实际窗口结束日取“今天”和该月月末中较早者。这样历史月不会越过月末，当前月也不会受用户所选结束日限制。

## 4. 数据流与组件边界

1. 日期解析层只负责判断是否单月，并返回 `targetRange`（完整自然月）与 `targetActualRange`（自然月月初至有效结束日）。
2. 目标读取层以 `targetRange` 查询月目标数据集，延续目标自然键去重、冲突/空键/负目标/零目标处理及 QA 计数。
3. 目标实际读取层以 `targetActualRange` 独立按“自然月 + 品牌名称 + 一级经销商代码 + 汇报车系名称”汇总 `当日订单数（首触）`，不得复用主销售聚合结果。
4. 目标合并和展示层继续只将命中有效目标自然键的实际订单纳入目标达成分子；主订单及其派生指标不受影响。
5. 导出中的“月目标、目标口径实际订单、目标达成率、月目标状态”等字段复用同一目标数据结果，确保页面和导出一致。

## 5. 页面状态

- 单月且有有效目标：顶部订单卡第二行和订单表现首行展示“月目标、目标达成”。
- 单月但无有效目标：隐藏两项文字，保留无障碍空槽。
- 跨月或未来月：进入 `invalid_range`，与“无有效目标”一致，隐藏两项文字和数值并发起零目标请求，不新增业务提示。
- 目标读取失败：保持既有“月目标数据暂不可用”降级；主销售链路照常展示。
- 目标为 0：保留月目标，目标达成留空；目标大于 0、实际为 0 时显示 `0.0%`；不封顶。

3. 选择 2026-06-25 至 2026-07-10：不展示月目标和目标达成；主销售结果保持可用。
4. 默认全部车系及具体车系，以及大区/小区/门店筛选下，目标自然键、行权限与月目标守恒规则不回归。
5. 页面与导出中目标字段在同一组织行保持一致；既有 1280px/1440px 布局和无横向滚动要求不回归。
