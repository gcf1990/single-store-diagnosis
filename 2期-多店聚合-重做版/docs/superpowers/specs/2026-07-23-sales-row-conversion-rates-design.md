# PC 销售概览行内四率双层漏斗设计

> 日期：2026-07-23
> 范围：仅 PC `multi-store-super-app/` 的“销售概览”表格第二列 `销售结果（指标：月环比）`。
> 状态：设计确认稿；本文件只定义前端展示与验收，不代表已开发、已测试或已发布。

## 1. 背景与目标

当前销售概览表格的“销售结果（指标：月环比）”单元格只展示 5 段数量漏斗：

`线索 → 到店 → 试驾 → 订单 → 零售`

每段包含当前数量和该数量的月环比。用户已选择 B 方案：在同一个单元格内采用“量在上、率在下”的双层漏斗，补充每一段转化关系的当前率和月环比，让门店/组织行可以同时看量级和转化效率。

目标：

1. 在销售结果单元格内新增 4 项转化率：线索到店率、到店试驾率、试驾订单率、交付率。
2. 保留现有 5 段横向漏斗的阅读顺序、数量值和数量月环比。
3. 不新增表格列，不新增交互，不改变销售概览、过程分析、打铁指标的 Tab 结构。

## 2. 非目标

1. 不修改顶部指标卡。
2. 不修改过程分析表和打铁指标表。
3. 不新增数据集、SQL、后端接口或诊断规则。
4. 不修改门店详情跳转、组织下钻、分页、车系筛选、权限白名单、排名和占比口径。
5. 不同步修改导出字段；本次先保持销售 CSV 导出不变，避免把视觉增强静默扩展成数据导出需求。

## 3. B 方案精确结构

单元格分上下两层：

### 3.1 上层：5 段数量漏斗

展示结构保持现状：

`线索 → 到店 → 试驾 → 订单 → 零售`

每个节点展示：

1. 阶段名称。
2. 当前数量。
3. 数量月环比。

数量月环比继续按现有销售结果逻辑展示，不因下层四率新增而改变。

### 3.2 下层：4 等分转化率

下层按 4 等分排列，对齐相邻漏斗阶段：

| 位置 | 展示项 | 对齐关系 |
|---|---|---|
| 1 | 线索到店率 | 线索 → 到店 |
| 2 | 到店试驾率 | 到店 → 试驾 |
| 3 | 试驾订单率 | 试驾 → 订单 |
| 4 | 交付率 | 订单 → 零售 |

每个转化率块展示：

1. 指标名称。
2. 当前率。
3. 月环比百分点差。

下层是上层漏斗的补充信息，视觉层级必须弱于上层数量。

## 4. 四项公式

所有比率均按当前行粒度的原始分子分母重算，不使用门店百分比简单平均。

| 指标 | 当前值公式 | 上月同期值公式 | 月环比 |
|---|---|---|---|
| 线索到店率 | 当前到店 / 当前线索 | 上月到店 / 上月线索 | 当前率 - 上月同期率 |
| 到店试驾率 | 当前试驾 / 当前到店 | 上月试驾 / 上月到店 | 当前率 - 上月同期率 |
| 试驾订单率 | 当前订单 / 当前试驾 | 上月订单 / 上月试驾 | 当前率 - 上月同期率 |
| 交付率 | 当前零售 / 当前订单 | 上月零售 / 上月订单 | 当前率 - 上月同期率 |

月环比是百分点差，不是相对涨跌率。展示文案可沿用现有 `+2.1% / -1.3% / --` 样式，但验收口径必须按百分点差计算。

## 5. 数据流与行粒度

1. 当前期使用销售概览行对象的 `row.current`。
2. 上月同期使用同一行对象的 `row.previous`。
3. 行对象由现有销售事实、有效经销商白名单、上游筛选、组织下钻和车系筛选聚合后得到。
4. 全国/大区/小区/门店/投资人组合店等任一展示行，都必须在该行聚合后的原始分子分母上重算四率。
5. “查看所有经销商”扁平模式下，四率按扁平后的经销商行各自计算；不读取或借用所属小区的比率。
6. 车系多选生效时，行内四率跟随销售概览销售事实的车系过滤；不得改用去车系的过程基线集合。

## 6. 与顶部四率的差异

顶部“过程指标”卡是当前范围总览；销售概览表格行内四率是组织/门店行级补充。

| 维度 | 顶部过程指标卡 | 销售结果单元格下层四率 |
|---|---|---|
| 粒度 | 当前页面范围总览 | 当前表格行 |
| 位置 | 顶部销售总览区域 | 销售概览表格第二列 |
| 前三项 | 线索到店率、到店试驾率、试驾订单率 | 同名，但按当前行重算 |
| 第四项 | 线索订单率 = 订单 / 线索 | 交付率 = 零售 / 订单 |
| 车系边界 | 具体车系下可使用过程基线保持总览口径 | 必须跟随销售概览行的销售事实和车系筛选 |

## 7. 信息层级与视觉规则

1. 上层数量是主信息：阶段名、数量、数量月环比保持当前漏斗样式。
2. 下层四率是次信息：字号、字重、颜色强度均低于上层数量。
3. 下层不使用卡片化大块背景，不新增强提示图标，不引入新的品牌色。
4. 下层可使用轻分隔线、浅背景或紧凑标签块区分 4 个转化关系，但不能造成“表中套卡”的视觉负担。
5. 表头仍服务整个单元格，可继续使用 `销售结果（指标：月环比）`；若后续要改表头文案，应另行同步上游文档。

## 8. 宽度、行高与响应式

1. 不新增列，销售结果仍在现有第二列内完成。
2. 1440px 下：上层 5 段漏斗单行展示，下层 4 项转化率单行展示，整行无页面级横向溢出。
3. 1280px 下：允许压缩间距和字号；上层仍必须单行，不能横向滚动；下层 4 项仍保持一行 4 等分。
4. 行高可从当前约 82px 增加到约 108-120px，以换取信息完整性；不得为了维持旧行高导致文字重叠或截断关键数值。
5. 窄屏或嵌入宽度不足时，指标名称可降级为短名：`到店率 / 试驾率 / 订单率 / 交付率`，完整名称进入 `title` 和可访问名称。
6. 操作列、主问题 / 结果断点列和 sticky 首列不得因本次改动被压缩到不可读。

## 9. 颜色语义

四项转化率均为“越高越好”：

1. 月环比大于 0：good / green。
2. 月环比小于 0：bad / red。
3. 月环比为 0、不可比较或无分母：neutral。

颜色只做增强，必须保留正负号和数值文本；不得只靠颜色表达涨跌。

## 10. 空值与错误语义

| 状态 | 当前率 | 月环比 |
|---|---|---|
| 当前分母 > 0，当前分子 = 0 | `0.0%` | 按上月同期可比性计算 |
| 当前分母 = 0 | `--` | `--` |
| 当前率有效，上月同期分母 = 0 | 当前率正常显示 | `--` |
| 销售主链路加载中 | 沿用现有表格加载态 | 沿用现有表格加载态 |
| 销售主链路失败、权限失败或数据错误 | 沿用现有整表错误/无权限状态 | 不在单元格内伪造 0 或 `--` |

`0.0%` 表示有有效分母且分子为 0；`--` 表示无有效分母或不可比较；数据错误必须走错误态，不得降级成空样本。

## 11. 交互与导出边界

1. 无点击、展开、hover 浮层或排序交互。
2. 不新增表格列。
3. 不新增导出字段；销售 CSV 暂按当前字段继续导出线索、到店、试驾、订单、零售及其数量月环比。
4. 如后续要求“页面可见即导出一致”，必须另起需求同步 Product-Spec、DEV-PLAN、导出字段、CSV 测试和数据验收。

## 12. 可访问性

1. 箭头为装饰元素，继续 `aria-hidden=true`。
2. 每个转化率块应提供完整可访问名称，例如：`线索到店率 当前 42.1%，月环比 增加 2.1 个百分点`。
3. 窄屏短名不应改变可访问名称。
4. 颜色语义必须有文本符号和数值兜底。
5. 单元格内新增信息不得制造新的键盘焦点，因为本次无交互。

## 13. 测试验收

1. 单元测试覆盖 4 项公式、分母为 0、分子为 0、上月分母为 0、百分点差和正负/中性色。
2. 组织聚合测试覆盖大区、小区、门店、投资人/扁平经销商行，确认按原始分子分母重算，不平均门店率。
3. 车系测试覆盖全部车系、具体单车系和多选车系，确认行内四率跟随销售概览行事实。
4. PC 回归覆盖 1280px 和 1440px 浅色/深色主题：无页面级横向溢出、上层 5 段单行、下层 4 项可读、主问题列和操作列不被挤压。
5. 空值/错误测试覆盖 `0.0%`、`--`、整表错误态和无权限态。
6. 导出回归确认销售 CSV 字段未新增，避免误判为导出遗漏。
7. 可访问性测试确认短名时仍有完整 `aria-label` 或等价可访问文本。
