## 1. 结论

采用用户已确认的图 2 方向：目标摘要不再位于标题行中间，改为并入“销售总览”左侧标题组，紧跟 `销售总览` 标题展示；最右侧车系筛选位置和交互不变。

标题行固定为左右两段：

`销售总览 + 订单目标 / 订单达成 / 零售目标 / 零售达成 / 时间进度` | `车系筛选`

v1.91 supersede v1.82 中“目标摘要位于标题行中间”的历史布局要求；v1.82 已发布测试 App 的实现和验收记录保留为历史事实。v1.79 的五项内容、时间进度公式、显示/隐藏/失败状态和 v1.81 的目标异步加载口径继续有效。

## 2. 信息架构

实现前结构：

`销售总览标题 + 车系筛选`

`独立销售经营进度条：订单目标 / 订单达成 / 零售目标 / 零售达成 / 时间进度`

`销售指标模块 / 过程指标模块`

v1.82 历史已实现结构：

`销售总览标题 + 行内目标摘要 + 车系筛选`

v1.91 当前已实现结构：

`左侧标题组：销售总览标题 + 行内目标摘要` + `右侧车系筛选`

`销售指标模块 / 过程指标模块`

固定阅读顺序：

1. 左侧标题组：`销售总览`
2. 紧跟标题：`订单目标`、`订单达成`、`零售目标`、`零售达成`、`时间进度`
3. 右侧：`车系`筛选器

下方仍直接进入两组指标：销售指标卡为 `订单 / 交付率 / 零售`；过程指标卡为 `线索到店率 / 到店试驾率 / 试驾订单率 / 线索订单率`。

## 3. 视觉规则

- 目标摘要为标题行辅助信息，紧跟 `销售总览` 标题，字号和权重弱于标题。
- 五项均为纯文字行内展示，不使用胶囊、独立卡片、边框、背景、阴影、状态圆点、箭头、达标标签或进度条填充。
- 订单目标、零售目标沿用目标蓝；订单达成、零售达成沿用达成绿；时间进度使用灰蓝色。
- 时间进度只表达本月日历进度，不表达目标是否达标，不随达成率变色。

## 4. 响应式数值边界

PC 断点以 1280px 为最小验收宽度：

| 视口 | 标题行要求 | 左侧标题组要求 | 车系筛选要求 |
|---|---|---|---|
| 1280px | 左右两段同一行展示 | `销售总览 + 五项` 必须单行完整展示；不得隐藏、换行、截断 | 保持最右侧可点击，不被挤出视口 |
| 1366px | 左右两段间距可比 1280px 略放宽 | 左侧组仍单行完整展示 | 宽度、展开入口和焦点状态不变 |
| 1440px 及以上 | 左右两段自然舒展 | 左侧组完整展示且摘要层级仍弱于标题 | 保持既有位置和交互 |

实现建议边界：

- 左侧标题组固定保留可读宽度，避免标题和摘要互相压缩。
- 车系筛选沿用既有触发器宽度约束，不因目标摘要改变为弹性过窄。
- 摘要优先收紧项间距和辅助字号；1280px 及以上禁止通过换行、省略号、隐藏某项或横向滚动解决空间。
- 1280px 以下不在本次验收范围；不得为移动端新增响应式入口或改动移动端需求。

## 5. 状态规则

| 状态 | 左侧标题组行为 | 下方销售/过程指标 |
|---|---|---|
| loading | 标题后紧接五段行内骨架，与五项最终位置对应 | 按 v1.81 先行展示真实销售/过程主数据，不等待月目标 |
| success | 标题后紧接固定顺序五项文字 | 直接进入销售/过程指标，卡片同起点、同高、同水平基线 |
| hidden | 无目标、跨月、未来月、非 MG 或目标被隐藏时，只显示 `销售总览` 标题，不留摘要空槽 | 指标模块位置、基线和卡片内容不变 |
| error | 标题后紧接 `月目标数据暂不可用` | 销售/过程主数据继续可用，不回退全局 loading |

不得在 hidden/error 状态下单独显示时间进度。

## 6. 数据流不变

- 订单目标、订单达成、零售目标、零售达成继续复用 REQ-011 目标链路。
- 时间进度继续使用页面运行时自然日：`dayOfMonth(today) / lastDayOfMonth(today) * 100%`，展示 1 位小数。
- 目标加载继续遵循 v1.81：销售事实、车系枚举和有效组织范围先解除主 loading；月目标后台加载，只局部更新左侧标题组目标摘要、表格目标槽和导出目标字段。
- 不新增目标数据源，不改目标自然键，不改订单/零售目标口径实际 SQL，不改车系集合，不改自然月窗口，不改组织归属，不改导出字段。
