# 单店销售诊断工作台

基于观远 Super APP 形态设计的单店销售诊断工作台 demo，用于展示销售漏斗、邀约、试驾和客户证据下钻。首期当前稿不展示门店 AI 诊断总览。

## 当前范围

本 demo 聚焦单店页面，不扩展全国或区域总览。

已覆盖模块：

- 顶部对象区：大区、小区、经销商、日期。
- 销售漏斗：线索、到店、试驾、订单及转化表现。
- 邀约/试驾：两个模块直接展示，模块内按小组展示过程指标。
- 深度分析：电话邀约、试驾接待、标签分布、顾问分布、客户明细和证据抽屉。

不在本期范围：

- 门店 AI 诊断总览。
- 现场问答。
- 实时重新诊断。
- 整改任务流写回。
- 全国/区域总览页面。
- 生产级调度平台线上化。

## 设计原则

当前 PRD 已确认以下核心边界：

```text
前端算展示公式，不算官方诊断；
前端算当前权限范围，不算跨组织官方排名。
```

具体分层：

| 类型 | 处理方式 |
|---|---|
| 原子事实数据 | 落入观远数据集或表单，并继承观远行权限。 |
| 门店内累计值、转化率、负向占比、环比 | Super APP 前端基于当前权限范围计算。 |
| 官方排名、官方分位、跨组织对标 | 数据层预计算。 |
| 主问题、结果断点、过程原因、优先动作 | 后续 AI 诊断阶段由 Codex T+1 诊断链路生成并沉淀；首期页面不展示门店 AI 总览。 |
| AI 解释文案 | 后续预留；首期页面不展示。 |

## 诊断生成链路

本期 MVP 方案采用：

```text
观远相关数据集完成刷新
-> Codex 每日定时任务触发
-> guancli 拉取门店销售指标、过程指标、IP打标明细、试驾打标明细
-> Codex 本地诊断脚本生成门店诊断结果
-> guancli 写入观远表单
-> 等待观远表单数据集每日定时刷新
-> Super APP 前端读取展示
```

生产级线上化调度不在本期范围内，后续需要迁移到不依赖个人本地 Codex 的稳定调度链路。

## 当前联调脚本

当前已拆成两条联调链路：

| 脚本 | 用途 | 是否可代表真实业务数据 |
|---|---|---|
| `scripts/run_mock_codex_diagnosis.py` | 使用全 mock 输入生成三张 Codex 输出表，验证写表链路 | 否 |
| `scripts/run_hybrid_codex_diagnosis.py` | 使用真实销售漏斗、真实 DCC 话务、真实试驾指标，并用 mock 打标明细补齐未上线数据源 | 需确认业务口径后才可运行 |
| `scripts/run_codex_diagnosis_job.py` | 一键串联真实指标取数、HYBRID 输出生成、当前态 upsert 写表和表单层反查 | 当前测试范围可用；正式需替换真实打标数据集 |
| `scripts/guancli_form_load.py` | 将生成的三张输出表通过 guancli 写入观远表单，默认按业务主键 upsert | 是写表工具，不定义业务口径 |
| `scripts/validate_codex_batch_visibility.py` | 校验指定批次是否已写入三张观远表单 | 是验收工具，不判断业务口径 |

`run_hybrid_codex_diagnosis.py` 对关键口径采用显式确认参数。未确认销售聚合范围、DCC 去重规则、试驾日期归属字段和 mock 打标范围时，脚本会直接中止，不生成业务结果。
