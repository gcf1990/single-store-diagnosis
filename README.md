# 单店销售诊断工作台

基于观远 Super APP 形态设计的单店销售诊断工作台 demo，用于展示门店销售漏斗、邀约过程、试驾过程、AI 诊断总结和客户证据下钻。

## 项目内容

| 文件 | 说明 |
|---|---|
| `index.html` | 单店诊断工作台前端静态 demo。 |
| `单店销售诊断工作台_PRD.md` | 当前页面范围对应的 PRD，供后续 Codex / AI Agent 开发、联调和测试使用。 |
| `平台开发计划0621.xlsx` | 当前平台开发计划和任务节奏记录。 |

## 当前范围

本 demo 聚焦单店页面，不扩展全国或区域总览。

已覆盖模块：

- 顶部对象区：大区、小区、经销商、月份。
- AI 诊断总览：总体诊断结论、结果断点、过程原因、优先动作。
- 销售漏斗：线索、到店、试驾、订单及转化表现。
- 邀约过程诊断：IP 电话相关过程指标和负向邀约表现。
- 试驾过程诊断：试驾里程、试驾时长和负向接待表现。
- 第三层明细：邀约技巧、接待技巧、标签分布、顾问分布、客户明细和证据抽屉。

不在本期范围：

- 现场问答。
- 实时重新诊断。
- 整改任务流写回。
- 全国/区域总览页面。
- 生产级调度平台线上化。

## 设计原则

当前 PRD 已确认以下核心边界：

```text
前端算展示公式，不算官方诊断；
前端算当前权限范围，不算跨组织官方排名。
```

具体分层：

| 类型 | 处理方式 |
|---|---|
| 原子事实数据 | 落入观远数据集或表单，并继承观远行权限。 |
| 门店内累计值、转化率、负向占比、环比 | Super APP 前端基于当前权限范围计算。 |
| 官方排名、官方分位、跨组织对标 | 数据层预计算。 |
| 主问题、结果断点、过程原因、优先动作 | Codex T+1 诊断链路生成并沉淀。 |
| AI 解释文案 | 正式版建议沉淀，前端可保留解释增强能力。 |

## 诊断生成链路

本期 MVP 方案采用：

```text
观远相关数据集完成刷新
-> Codex 每日定时任务触发
-> guancli 拉取门店销售指标、过程指标、IP打标明细、试驾打标明细
-> Codex 本地诊断脚本生成门店诊断结果
-> guancli 写入观远表单
-> 观远表单数据集刷新
-> Super APP 前端读取展示
```

生产级线上化调度不在本期范围内，后续需要迁移到不依赖个人本地 Codex 的稳定调度链路。
